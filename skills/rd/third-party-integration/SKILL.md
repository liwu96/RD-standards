# 三方接入流程

接入任何三方服务（支付/短信/OSS/大模型/外部 HTTP）或引入三方库时走本流程。规范依据：`rules/third-party/third-party-usage.md`。

## When to Activate

- 新接三方服务（同步或异步调用）
- 引入新的三方库/SDK（Maven 依赖 / Python 包）
- 三方调用线上故障复盘后的加固

## 步骤

### 1. 选型评审（引入前，提技术评审单）

- [ ] 必要性：现有依赖能否满足？同类库团队是否已有标准选型（HTTP 客户端、JSON 库只留一个）
- [ ] 维护活跃度（近 6 个月有发布）、社区规模、文档质量
- [ ] License：MIT/Apache-2.0 可用；GPL/AGPL 类禁止进闭源服务
- [ ] 版本与现有依赖无冲突（Java `dependency:tree` 对比 / Python 锁文件 diff）
- [ ] 成本与配额（QPS 限制、计费方式）

### 2. 稳定性五件套（代码必须全部落实）

按 `rules/third-party/third-party-usage.md` §2：

| 项 | 要求 | 默认值 |
|---|---|---|
| 超时 | 连接+读超时显式设置 | 按 P99×2~3 |
| 重试 | 仅幂等接口；≤3 次指数退避+抖动 | 3 次 |
| 熔断 | 连续失败熔断+降级 | 半开探测恢复 |
| 隔离 | 独立线程池/连接池上限 | 与主业务隔离 |
| 限流 | 客户端限流保护配额 | 按对方配额 |

- [ ] 降级路径明确：默认值 / 缓存快照 / 友好提示（C 类错误码）
- [ ] 同步调用失败且无法降级才返回 `C` 类码；异步失败走重试+告警+补偿

### 3. 密钥与安全

- [ ] key/secret 进配置中心或环境变量，禁止入代码/日志/git 历史
- [ ] 日志与异常输出脱敏（token、签名只打前后 4 位）
- [ ] 出网走统一网关/代理
- [ ] 资金/短信类：防重放（频控、验证码、数量限制）

### 4. 可观测与对账

- [ ] 埋点：耗时、成功率、错误码维度指标 + 告警
- [ ] 调用日志带 `requestId` 贯通全链路
- [ ] 资金类（支付/退款）：对账任务 + 差异补偿，以我方流水为准

### 5. 上线

- [ ] 预发联调（mock 单测 + 真实联调环境）
- [ ] 灰度发布 + 回滚方案（配置开关控制三方调用）
- [ ] 上线首日重点观察三方错误率与超时占比

## 产出格式

```markdown
## 三方接入评审：<服务名>
- 用途与调用方式：同步/异步、QPS 预估
- 五件套配置：超时/重试/熔断/隔离/限流 具体值
- 错误码映射：C01xx（支付）/C02xx（短信）/...
- 密钥存放：配置中心 key 名
- 降级方案：
- 对账：需要/不需要
- 灰度与回滚：
```

## 打回条件

- 无超时或无限等待；非幂等接口自动重试
- 密钥出现在代码/日志；无监控埋点
- 资金类无对账；无降级方案
- 三方库 License 传染或与现有依赖冲突未处理
