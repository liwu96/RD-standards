# 测试规范（通用基线）

> 适用范围：团队所有后端服务。语言专项细则见 `rules/java/java-backend-standard.md` §10（单元测试）与 `rules/python/python-backend-standard.md` §26。

## 1. 测试分层

| 层 | 占比目标 | 范围 | 运行环境 |
|---|---|---|---|
| 单元测试 | 最多 | 函数/类级业务逻辑，依赖全部 Mock | 无外部依赖，毫秒级 |
| 集成测试 | 中 | 接口 + 数据库 + 中间件（测试环境实例） | 测试库/容器，秒级 |
| 端到端（E2E） | 最少 | 核心用户链路（下单、支付、登录） | 预发环境，分钟级 |

- 【强制】比例遵循测试金字塔：禁止"只有 E2E"或"全靠手工"。
- 【强制】单测不依赖网络、服务、中间件（数据库用事务回滚或内存实现，三方用 Mock）。对应 AIR 原则（Automatic/Independent/Repeatable）。

## 2. 覆盖率要求

- 【强制】核心业务、核心应用、核心模块的增量代码单测必须通过（增量无测试不合入）。
- 【推荐】语句覆盖率基线 70%，核心模块语句 + 分支覆盖率 100%（与《阿里巴巴 Java 开发手册》一致）。
- 【推荐】覆盖率在 CI 卡点（Jacoco / pytest-cov），只对增量代码卡，避免历史欠债阻塞交付。

## 3. 用例设计

- 【强制】遵守 BCDE：Border 边界值、Correct 正确输入、Design 结合设计文档、Error 强制错误输入。
- 【强制】用例独立：不互相调用、不依赖执行顺序、可重复执行。
- 【推荐】AAA 结构（Arrange-Act-Assert）；命名说明行为：`test_export_orders_empty_range_returns_empty`。
- 【强制】用断言验证结果，禁止 print/日志人工核对。
- 【强制】修 bug 先写复现用例再修复（回归测试防止再犯）。

## 4. TDD（推荐流程）

新功能与 bug 修复推荐测试先行：

```
1. 写测试（RED：运行确认失败，且失败原因正确）
2. 最小实现（GREEN：测试通过）
3. 重构（保持绿灯）
4. 验证覆盖率
```

## 5. 集成与 E2E 要点

- 【强制】集成测试数据用程序构造（fixture/factory），禁止依赖手工插入的"魔法数据"。
- 【强制】测试产生的数据有标识（统一前缀 `IT_`）或事务回滚清理。
- 【推荐】E2E 只覆盖资金、订单等核心链路，用真实测试账号 + 幂等清理。
- 【推荐】三方依赖在集成测试中用挡板（stub server / wiremock），联调放预发。

## 6. CI 集成

- 【强制】PR 触发：构建 + 静态检查 + 单测 + 覆盖率卡点；失败禁止合入。
- 【推荐】每日主干任务：全量测试 + 集成测试；E2E 按需（发布前/每日夜间）。
- 【推荐】测试失败优先级高于新功能开发；flaky 用例当天标记隔离并限期修复。
