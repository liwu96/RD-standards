# 状态码与错误码规范

> 适用范围：团队所有 HTTP API 的业务状态码、错误码枚举定义。
> 设计原则：HTTP 状态码表达"协议层"结果（网关/负载均衡/客户端均可识别），业务 `code` 表达"业务层"结果；两者配合使用，禁止只用其一表达全部语义。

## 1. 编码方案

【强制】业务码采用 **`0` 表示成功，非 0 表示失败**；错误码为 5 位字符：**1 位大写字母（错误大类）+ 4 位数字（具体错误）**。

| 大类 | 含义 | 责任方 |
|---|---|---|
| `0` | 成功 | — |
| `A` | 用户端错误（参数、鉴权、权限、状态、频控） | 调用方/用户 |
| `B` | 系统端错误（应用自身、依赖的中间件） | 服务提供方 |
| `C` | 第三方服务错误（支付、短信、OSS 等） | 服务提供方协调三方 |

- 数字段前两位表示子域，后两位表示具体错误，例如 `A0301` = A（用户端）03（权限域）01（无权操作该资源）。
- 【强制】错误码一经发布对外，语义不可变更；需要调整时新增错误码并废弃旧码（旧码保留映射至少一个大版本）。
- 【强制】错误码全团队统一维护在一处（错误码登记表，见 §5），禁止各服务私造重复语义的码。

## 2. 通用错误码枚举（必选实现）

各服务必须实现以下基础错误码；业务专属错误码在对应子域下扩展。

### A 类：用户端错误

| code | HTTP | 含义 | message 示例 |
|---|---|---|---|
| A0100 | 400 | 参数校验失败（details 返回字段级错误） | 参数不合法：pageSize 超过上限 100 |
| A0101 | 400 | 缺少必填参数 | 缺少必填参数：orderId |
| A0102 | 400 | 参数格式错误（时间/JSON 等） | 时间格式必须为 RFC 3339 |
| A0200 | 401 | 未登录或 token 缺失 | 请先登录 |
| A0201 | 401 | token 已过期 | 登录已过期，请重新登录 |
| A0202 | 401 | token 无效/被篡改 | 登录态校验失败 |
| A0300 | 403 | 未授权访问该接口 | 无权访问该接口 |
| A0301 | 403 | 无权操作该资源（水平越权拦截） | 无权操作该资源 |
| A0400 | 404 | 资源不存在 | 资源不存在 |
| A0500 | 409 | 资源冲突（重复创建） | 记录已存在 |
| A0501 | 409 | 状态冲突/版本冲突（乐观锁） | 数据已被修改，请刷新后重试 |
| A0600 | 410 | 资源已删除/失效 | 资源已失效 |
| A0700 | 429 | 触发限流 | 请求过于频繁，请稍后再试 |
| A0701 | 429 | 触发风控/防刷 | 操作过于频繁，请稍后再试 |
| A0800 | 408 | 客户端请求超时（客户端主动取消按此记录） | 请求超时 |

### B 类：系统端错误

| code | HTTP | 含义 |
|---|---|---|
| B0001 | 500 | 服务内部错误（未分类异常兜底） |
| B0100 | 500 | 数据库访问异常 |
| B0101 | 500 | 数据库死锁/锁等待超时 |
| B0200 | 500 | 缓存服务异常（仅当降级失败时返回） |
| B0201 | 503 | 服务不可用（发布中/熔断开启/依赖崩溃） |
| B0300 | 500 | 消息队列投递失败 |
| B0400 | 500 | 配置错误（配置缺失/非法，通常为发布事故） |

### C 类：第三方服务错误

| code | HTTP | 含义 |
|---|---|---|
| C0000 | 502 | 第三方服务错误（未细分兜底） |
| C0100 | 502 | 支付渠道调用失败 |
| C0200 | 502 | 短信/邮件通道失败 |
| C0300 | 502 | 对象存储（OSS/S3）调用失败 |
| C0400 | 502 | 其他外部 HTTP/RPC 依赖失败 |

> C 类仅在**同步阻塞调用**三方且无法降级时返回；异步调用失败不得直接透出给用户，走重试 + 告警 + 补偿。

## 3. HTTP 状态码使用约定

- 【强制】网关与负载均衡依赖标准 HTTP 语义，因此：2xx 一定业务成功或业务失败可结构化表达（本团队约定 2xx 仅用于成功；业务失败一律 4xx/5xx，见下）；
- 【强制】映射关系以 §2 表格为准，禁止 200 + 错误 code 的组合（监控无法基于状态码统计错误率）。
- 【参考】未在表中出现的 HTTP 码（405、413、415 等）由框架/网关自动产生，不需要业务定义。

## 4. 枚举实现（Java / Python）

【强制】错误码定义为语言原生枚举，集中存放于公共包（如 `common-error` 模块 / `common.errors` 包），禁止魔法字符串散落在业务代码中。

**Java：**

```java
public enum ErrorCode {
    OK("0", "success"),
    INVALID_PARAM("A0100", "参数校验失败"),
    UNAUTHORIZED("A0200", "请先登录"),
    FORBIDDEN_RESOURCE("A0301", "无权操作该资源"),
    NOT_FOUND("A0400", "资源不存在"),
    CONFLICT("A0500", "记录已存在"),
    LOCK_VERSION_CONFLICT("A0501", "数据已被修改，请刷新后重试"),
    RATE_LIMITED("A0700", "请求过于频繁，请稍后再试"),
    INTERNAL_ERROR("B0001", "服务开小差了，请稍后再试"),
    DB_ERROR("B0100", "数据服务异常"),
    SERVICE_UNAVAILABLE("B0201", "服务暂不可用"),
    THIRD_PARTY_ERROR("C0000", "第三方服务异常");

    private final String code;      // OK 用 "0"
    private final String message;
    // 构造器与 getter 略；message 允许被上层覆写为更具体的提示
}
```

**Python（pydantic v2 / enum）：**

```python
from enum import Enum

class ErrorCode(str, Enum):
    OK = "0"
    INVALID_PARAM = "A0100"
    UNAUTHORIZED = "A0200"
    FORBIDDEN_RESOURCE = "A0301"
    NOT_FOUND = "A0400"
    CONFLICT = "A0500"
    LOCK_VERSION_CONFLICT = "A0501"
    RATE_LIMITED = "A0700"
    INTERNAL_ERROR = "B0001"
    DB_ERROR = "B0100"
    SERVICE_UNAVAILABLE = "B0201"
    THIRD_PARTY_ERROR = "C0000"

DEFAULT_MESSAGES: dict[ErrorCode, str] = {
    ErrorCode.OK: "success",
    ErrorCode.INVALID_PARAM: "参数校验失败",
    # ...与上表一致
}
```

## 5. 错误码登记与治理

- 【强制】新增错误码必须提 PR 更新本文件 §2 表格与公共枚举包，评审人负责查重。
- 【强制】`A0100` 参数错误的 `data.details` 结构固定为字段级数组：

```json
{
  "code": "A0100",
  "message": "参数校验失败",
  "data": {
    "details": [
      { "field": "pageSize", "reason": "必须为 1~100 的整数" }
    ]
  }
}
```

- 【推荐】监控与告警基于 `code` 维度聚合（网关侧按 HTTP 码、应用侧按业务码），B/C 类错误率突增自动告警。
- 【参考】message 面向最终用户可读；面向开发者的排查信息（异常堆栈、内部上下文）只写日志，并通过 `requestId` 关联。
